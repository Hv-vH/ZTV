# 菜单性能修复

2026-10-23。基线为 `832f274`（0.3.0），修复后为 0.3.1；视觉更新在此修复之后单独接入。

## 问题与修复

原版在首次打开菜单时，将全天 114 个节目全部创建为嵌套的原生卡片；连同频道区等，共持有 1,020 个 View。Simpleperf 捕获到 `MainActivity.renderProgramGuide` → `TvMenuViews.ProgramCard.<init>`。菜单隐藏时仍绑定频道数据，焦点与网络通知还会重复执行同步绑定。全屏菜单已经覆盖播放器时，WebView 仍合成被遮住的视频画面。

- 将节目区改为框架 ListView + BaseAdapter，复用可见卡片；数据保留完整一天，不裁掉节目。
- 使用逻辑节目索引处理遥控器导航，等待目标行布局后再恢复焦点；关闭菜单时取消待恢复焦点，防止旧回调抢焦点。
- 合并同一轮主线程里的菜单更新；隐藏菜单不绑定 UI，重新打开时读取最新缓存。
- 缓存焦点/直播/普通背景、标签背景、字重与进度颜色；内容未变时跳过 TextView 重新赋值。
- 菜单打开时将 WebView 设为 INVISIBLE，关闭时恢复 VISIBLE；不调用 onPause、不重新加载当前频道。
- Debug 日志 `ZtvMenuPerf` 记录 `bindMs`：只测菜单同步处理，不代表完整首帧或端到端加载时间。

列表复用依据 Android 官方说明：https://developer.android.com/topic/performance/issues/render 。

## 可比测试

用户的 Television_4K AVD：Android TV API 36 arm64。4K 下采用软件渲染，绝对帧耗时噪声很大。为隔离应用端开销，在同一镜像临时使用 1920×1080、density 320；与原 3840×2160、density 640 均为 960×540dp。基线和修复版使用同一设置。

每个版本进行三轮冷启动，等待节目数据就绪后首次打开菜单，再连续开关 40 次；共各 120 次压力开关。基线仅加入与修复版相同的 Debug 计时，没有其他改动。

| 指标 | 基线 0.3.0 | 性能修复 |
| --- | --- | --- |
| 首次菜单同步绑定，三轮 | 184 / 189 / 166ms | 29 / 45 / 21ms |
| 首次绑定中位数 | 184ms | 29ms |
| 首次菜单原生 View | 1,020 | 139 |
| 每轮 40 次开关后 View | 1,020 | 139 |
| 120 次连续开关 | 响应正常，无捕获到的 ANR / crash | 响应正常，无捕获到的 ANR / crash |

同步绑定中位数降低约 84%，原生 View 减少约 86%。这不是对物理电视帧率、整体启动速度或所有卡死情形的保证。基线压力测试也未复现用户报告的偶发卡死；修复针对已确认的视图创建与重复绘制开销。

## 行为回归

- 正式 0.4.0 在原始 4K 设置下 15 项遥控器流程通过：当前频道定位、左右边界、节目/刷新焦点、手动刷新、午夜首节目、长按、同频道确认、其他频道切台与返回层级。
- 本地 WebView 调试验证：打开菜单时播放时间持续推进、音频解码字节增加、muted=false、volume=1；关闭后页面 performance.timeOrigin 不变，播放继续。证明未切换或重载页面，不代替真实电视扬声器听测。
- 4K 扩展流程 8 项通过：从 00:00 连续浏览全天 114 项至末项、上下边界、反向复用、浏览全部频道及 200 次快速菜单开关；长列表预热后 View 为 183，200 次开关后仍为 183，无捕获到的 ANR / crash。跨出可见列表时先让 ListView 持有焦点，再交给目标行，防止系统把焦点转入频道列。
- 30 项节目单单元测试与 7 项播放器脚本测试通过；APK 构建、Android Lint 通过（0 错误，7 个既有警告）。

原始证据在 `app/build/qa/performance/`：`before/` 为原 4K 采样；`before-1080/`、`after-1080/` 为对比三轮的计时、帧统计、meminfo、界面树与异常记录；`after/playback-continuity.json` 为视频连续性检查；`app/build/qa/v04/` 为正式 4K 扩展、加载/重试和截图证据。构建证据不纳入 Git。

## 0.4.1 加载动效

指示条使用一个缓存的 ObjectAnimator，仅平移轨道内的小段 View；没有逐帧布局或资源分配。文本轮询不重新启动它。首帧撤罩、失败、菜单覆盖、后台、窗口不可见与 View 分离时停止，系统禁用动画时采用静态标记。

在原始 4K 软件渲染模拟器中，三张连续截图确认指示段位置变化；加载时 1.1 秒窗口记录到 18 帧，菜单覆盖后同长度窗口为 0 帧。该采样只用于证明运动存在及遮挡后停止，软件渲染下的卡顿数据不能代表物理电视帧率。新增焦点/菜单回归含 20 次连续开关，未出现卡死；旧版本的完整性能对比不重复计入本次测试。

证据：`app/build/qa/v041/motion-positions.json`、`loading-frames.txt`、`loading-menu-frames.txt`、`ui-checks.json` 与 `loading-checks.json`。
