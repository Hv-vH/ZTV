# 新蓝 TV 界面设计

版本：0.4.0。日期：2026-10-23。开发分支：`fix/tv-menu-performance`。

## 已确认方向

按用户指定的 web-design-engineer 流程，先确认炭灰、暖白与琥珀色系统，再提供菜单/加载页初稿；用户确认初稿后接入原生 Android。保留左右双栏、频道顺序、全天节目与遥控器操作。`design/v0/` 是评审稿，应用继续使用原生 View。

频道摘要最多两行，右侧完整节目名称自然换行。字体只在应用初始化时读取和缓存，字号变化不重新载入文件。原生字体为兼容 API 23 的静态子集，缺字使用系统回退，源许可与修改说明随 APK 分发。资源与提示词见 [品牌说明](../brand-spec.md) 和 [生成记录](../design/v0/assets/GENERATION.md)。

## 加载与失败

- 原生深色加载页位于网页之上，显示本次生成的 Z 品牌图标、频道名、连接状态、频道序号与遥控器提示。
- 新 WebView 通过 `requestVideoFrameCallback` 确认实际视频帧；旧版本在解码数据就绪后等待两个渲染机会。不会仅凭 `paused=false` 就撤掉遮罩。
- 关闭 HTML 原生控件并移除网站海报；若网站再次添加这些属性，立即移除。WebChromeClient 提供纯黑默认海报，避免默认大播放图标。
- 连接、准备画面、有声播放被拦截、连接失败/超时分别显示对应提示。网络失败按 OK 重新连接当前频道；节目单仍可打开并切换频道。
- 只保留一条播放检查链，切台、暂停与销毁使旧检查失效；菜单中等待首帧时延后超时判断，收起菜单后继续检查。

视频帧与默认海报机制依据 [MDN 视频帧回调](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback) 和 [Android WebChromeClient](https://developer.android.com/reference/android/webkit/WebChromeClient#getDefaultVideoPoster())。

## 保留与加固的交互

- 频道区左键停留；刷新按钮继续右键停留。
- 频道右键进入当前节目，节目右键直达刷新；上下支持长按。
- 当前频道确认只关闭菜单，不重新加载；其他频道才切台。没有回看与点播入口。
- 返回从节目到频道，再关闭菜单。菜单键直接开关。
- 列表只创建可见行并复用；跨出可见区域时由列表暂时持有焦点，目标行布局后交还，防止 Android 把焦点移回频道区。
- 菜单覆盖播放器时隐藏 WebView 的显示层，保留页面、音频和播放进度；关闭后恢复显示。

## 验证与证据

- 用户的 Television_4K AVD，Android TV API 36 arm64。最终界面使用原始 3840×2160 / density 640，即 960×540dp。
- 30 项节目单单元测试，7 项播放器脚本测试；APK 构建与 Android Lint 通过，0 错误、7 项既有警告。
- 实测延迟连接下的原生加载页、首帧后撤罩、海报/控件被网站重加后仍隐藏、断网错误与 OK 恢复；网络模拟条件均已恢复。
- 15 项完整遥控器回归与 8 项扩展流程通过；全天 114 项首尾浏览、反向复用、跨频道和 200 次 4K 快速开关均响应正常。长列表预热后 183 个 View，压力开关后仍为 183；未捕获到 ANR / crash。
- 真实 4K 画面与检查输出：`app/build/qa/v04/`。菜单、节目焦点、加载、错误、最后节目与直播截图均来自模拟器。
- 性能基线、同步处理计时、视图数量与限制见 [性能说明](PERFORMANCE.md)。

模拟器的播放状态与音频解码记录不能替代物理电视扬声器听测；不同电视的 WebView 与解码兼容性仍需真机回归。
